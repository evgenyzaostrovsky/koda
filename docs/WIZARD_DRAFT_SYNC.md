# Синхронизация черновика мастера

2026-10-22. Приложение не публиковалось. Миграция0017 применена к Supabase КОДА после отдельного разрешения пользователя; SQL Editor сообщил Success.

## Поведение

- Локальный черновик по-прежнему сохраняется сразу, отдельно для UUID аккаунта; гостевой черновик в облако не переносится.
- Полный черновик (желание, формулировка, этап, направления, вопросы и сырые частичные ответы) синхронизируется через goal_wizard_drafts. Пустые ответы сохраняют позиции относительно вопросов.
- Облако хранит неизменяемые целые версии с ID и родителями. Повтор отправки того же ID не создаёт дубль и не меняет сохранённое содержимое. Новые снимки отправляются с задержкой после ввода, а не на каждый символ.
- Проверка обновлений идёт при открытии, возврате фокуса, восстановлении связи и периодически, пока экран целей смонтирован. Локальный текст не ждёт сети. Ошибка синхронизации показывает локальный статус и не стирает ответы.
- Одновременные ветки не смешиваются по полям. Мастер показывает вопросы и ответы обеих версий и предлагает выбрать целый черновик. Выбор создаёт новую объединяющую версию; исходные снимки остаются в облаке.
- Успешное создание цели сохраняет отметку завершения черновика. Старая офлайн-правка при столкновении с завершением создаёт конфликт, а не молча возвращает старый черновик.
- Перед и после каждого обращения адаптер проверяет текущую сессию; поздний ответ от старого аккаунта не применяется к форме другого.

## База

supabase/migrations/0017_goal_wizard_drafts.sql — отдельная таблица с PK(user_id, revision_id), неизменяемыми снимками и RLS auth.uid()=user_id. Authenticated может только SELECT/INSERT собственных строк; UPDATE/DELETE и анонимный доступ запрещены. Существующие таблицы не менялись. Содержимое ревизии ограничено 64KiB; клиент проверяет полную структуру, граф родителей и коллизии ID. Лимиты — 10 000 ревизий и 256 конфликтных родителей; при превышении синхронизация останавливается с сохранением локального черновика. Автоматического удаления истории нет.
