# Контекст всего роадмапа и уточнения

Локальные изменения от 2026-10-22. Без публикации и изменения схемы БД.

Помощник направлений передаёт `clarifyRoadmap: true`. Он умеет показать 1–2 вопроса вместо плана, передать ответы в следующий запрос и показать `planningNote`, если продолжение пока нельзя обосновать. Пустой ответ означает «не знаю». Вопросы относятся к текущим условиям; изменение цели, контекста или времени исключает старые вопросы из следующего запроса. Ответы участвуют в проверке актуальности предложения. Это отдельный сценарий от мастера формулировки новой главной цели.

Сам `planningContext` продолжает сохраняться и синхронизироваться прежним механизмом. В последующей итерации ответы помощника стали отдельной сохраняемой частью контекста цели — см. `ROADMAP_ANSWERS_QA.md`. Они не дописываются молча в свободный текст. Новая схема БД не вводилась.

Адаптивная карта содержит до восьми этапов. Строгое заполнение всех 64 шагов остаётся отдельным выбором. Число ячеек не должно заставлять модель придумывать работу. Предложение просматривается и применяется пользователем отдельно; вопросы и ответы сами по себе не меняют структуру цели.

Сервер передаёт нумерованный список источников из контекста и ответов. Модель выбирает источник для каждого этапа; сервер проверяет идентификатор и сам восстанавливает текст источника. Это заменяет требование к модели дословно копировать цитату: в живом прогоне небольшое перефразирование раньше создавало ложный отказ. Ссылки на источник не доказывают смысловую верность каждого действия. Дополнительно отклоняются известные общие пустышки, включая поздние этапы; промпт запрещает приписывать учебнику неуказанное содержание. Предложить собственное небольшое упражнение по подтверждённой теме допустимо, утверждать наличие конкретного неизвестного упражнения в учебнике — нет.

После недостаточно обоснованного ответа сервер предлагает уточнение; после уже полученных ответов может вернуть только объяснение ограничения, без повторного опроса и выдуманного плана. Ошибка формата/обоснования ответа помощника описывается отдельно от нехватки пользовательских фактов.

## Семантическая проверка

Независимый живой CSV-прогон доказал ограничение ссылок на источники: структурно корректный план всё равно предлагал исправлять неизвестные пропуски, искать сезонность без известной длительности наблюдений и объяснять причинное влияние по date/product/revenue. Запись `.tmp/roadmap-csv-live.json` помечена `structuralPassed:true`, `semanticPassed:false`; её нельзя использовать как доказательство корректного плана.

Для новых full-map запросов с `clarifyRoadmap` добавлен отдельный короткий аудит всех действий. При найденных дефектах допускается одна попытка исправления и обязательный повторный аудит. Аудит использует стабильные внутренние actionId; исправление возвращает только патчи отмеченных действий. Неизменённые тексты, реальные слоты и защищённая история сохраняются сервером. Неверные идентификаторы/формат, оставшиеся дефекты, неподтверждённый ответ или исчерпанный срок не выпускают применяемый план.

На цикл отведено 45 секунд, максимум четыре обращения к выбранному провайдеру. Это увеличивает число API-вызовов по сравнению с прежней генерацией. Обычный стартовый сценарий без этого режима сохраняет один вызов. Сетевые функции принимают оставшийся бюджет и ограничивают отдельный запрос прежними 40 секундами. Смысловая проверка тоже выполняется моделью и не является формальным доказательством истинности; пользовательское подтверждение плана остаётся обязательным.

В этой итерации воспроизведён старый перекос на живом Яндексе: при «освоить основы испанского», уроке 5 и меню Sol модель предлагала неизвестный урок 6 и общую грамматику. Этот случай используется как регрессия, а не считается успешным результатом.

Проверено до финального прогона модели:

- `npm run typecheck`, `npm run test:goal-ai`, `npm run test:open-window` — PASS (последующие узкие изменения дополнительно проверяются отдельно).
- Независимая QA воспроизвела P2: full-map мог выбрать публикацию в GitHub при противоречащем ответе «только локальный файл». Добавлен обязательный `answerStatus` для уточнённого роадмапа; conflicting и отсутствующий статус дают пояснение без применяемого плана. QA подтвердила исправление узким прогоном.
- `uncertain` требует пояснения ограничения; подтверждённые частичные этапы допустимы с этим пояснением. Узкая QA-проверка прошла.
- Реальный локальный браузер: исходный испанский контекст восстановился; помощник задал два вопроса о критерии результата и будущих темах. Два ответа «не знаю» дали пояснение без нового опроса и без кнопки применения плана.
- Проверка формы на ширине 390 px: оба вопроса, поля и кнопка доступны, текст переносится, скролл работает. Временный размер экрана сброшен.
- Найден и исправлен UI-край: после редактирования ответов старое пояснение о нехватке данных скрывается; сообщение о запрете сохранения устаревшего плана показывается только при наличии самого плана.

Скриншоты: `koda-roadmap-grounding/unknown.png` и `mobile-questions.png` в каталоге визуализаций задачи.

## Итоговая проверка

После финальных изменений `npm run typecheck` и полный `npm run test:goal-ai` завершились с кодом 0. Независимая QA повторно выполнила целевые review-тесты: исправление только отмеченных действий, защита сохранённых дел, реальные slotIndex при разреженной карте, строгий режим 64 шагов, неверный аудит и общий дедлайн. Проверка браузера проводилась координатором на отдельном локальном audit-превью 8103, без Supabase и без применения предложения к реальной цели.

Реальные ответы Яндекса прочитаны целиком, а не оценены только по формату:

- Испанский: первоначально два вопроса о критерии результата и следующих темах. Финальный браузерный запрос после ответов дал 5 этапов / 5 шагов: просьба о счёте, автобус, маршрут, отель, цена. Уже освоенные алфавит, знакомство и заказ еды не повторяются; каждый учебный шаг ограничен одной фразой. Новые курсы и покупки не предлагаются. Полный AX: `spanish-final-ax.txt`, скриншот: `spanish-final.png` в каталоге доказательств задачи. Отдельный API-прогон дал 5 этапов / 10 шагов по тем же темам.
- CSV: уточнён формат публикации. Итог — 8 этапов / 16 действий до notebook и README в существующем GitHub-репозитории. Вместо удаления аномалий — анализ и выбор политики обработки; нет причинных/сезонных утверждений, загрузки исходного CSV или изменения доступа. Синтетический результат `.tmp/roadmap-csv-live.json`, трасса четырёх ответов `.tmp/roadmap-csv-trace.json`. Некоторые действия при 20 минутах всё ещё сформулированы шире, чем идеальный микрошаг; это ограничение качества, а не доказанная оценка длительности.
- Нехватка сил: исходный стартовый сценарий с 10 минутами дал одно действие — проверить пропуски в уже открытом CSV; без установки инструментов, курсов и ежедневного режима. Артефакт `.tmp/roadmap-starter-live.json`. Стартовый поток не переводился на многошаговый аудит.

Живые прогоны выявили ложные пропуски модельного аудита. Добавлены узкие детерминированные проверки новых предложений: изменение пропусков/аномалий без выбранной политики, необоснованная сезонность/причинность, неограниченные учебные наборы при короткой сессии, второй репозиторий при уже имеющемся. После ремонта выполняется повторный аудит и те же проверки. Ранее сохранённые дела в additive-режиме сохраняются, а в rebuild защищены завершённые дела и рутины.

Выявлен и исправлен излишний отказ: проверяющий спрашивал необязательные предпочтения визуализации и оценку времени, которое уже передано. Prompt теперь ограничивает вопросы существенными неизвестными фактами. Это всё ещё модельное правило: универсальной гарантии отсутствия лишних вопросов или выдумок нет. Эвристика сезонности также не является статистической проверкой достаточности ряда.

Были сетевые отказы и ответы, не прошедшие повторную проверку: интерфейс показывал честное пояснение без кнопки применения. Это не засчитывалось как успешная генерация плана; окончательные успешные результаты получены последующими реальными запросами. Изменения не опубликованы, схема БД и реальные записи пользователя не менялись.
