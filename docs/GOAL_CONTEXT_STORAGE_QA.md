# Сохранение контекста ИИ в цели — 2026-10-22

Контекст поля «Где ты сейчас и что уже есть?» теперь хранится в optional Goal.planningContext. Ввод автоматически обновляет только это поле через функциональный updater текущей цели. Отдельного подтверждения или запроса ИИ для сохранения не требуется. При открытии помощника значение читается непосредственно из выбранной цели и передаётся как currentState в существующий запрос ИИ. Текст можно дополнять и полностью очищать.

Нормализация сохраняет пробелы, переносы и пустую строку, ограничивая текст 2000 символами. Старые цели без поля совместимы. mergeGoals отличает отсутствие поля у старого клиента от явной очистки пустой строкой.

Миграция БД не нужна: поле передаётся в существующем user_app_state.goals (jsonb). Локальное сохранение использует прежнее хранилище приложения с ключом аккаунта. Реляционная проекция goals не является источником восстановления этого поля.

Проверки:
- npm run typecheck — PASS.
- test-goal-context.ts — PASS: нормализация, JSON reload, clear, legacy merge, отдельные цели и аккаунты, offline retry и конкурентная CAS-запись через настоящий writeAppStateSnapshot с локальным mock API.
- test:open-window и test:sync — PASS, проверены исполнителем данных; отдельный test:goal-context также проверен QA.
- Координатор в браузере на изолированном 127.0.0.1:8101: ввод многострочного текста без запроса ИИ; закрытие/повторное открытие помощника; обновление страницы; закрытие вкладки и открытие новой — текст восстановился.
- Две тестовые цели: у новой поле пустое; после ввода другого текста контекст первой остался прежним. После очистки первой и reload первая пуста, вторая сохраняет собственный текст. На reload приложение может выбрать другую цель, поэтому проверялась конкретная цель через список.
- Пользовательские данные на 8098 не менялись. Публикации не было.

Скриншот восстановленного поля: koda-saved-context/restored.png в каталоге визуализаций задачи.

Ограничения: живые записи Supabase и два реальных устройства в этой задаче не проверялись; облачный транспорт проверен mock API. Два конкурирующих непустых контекста разрешаются существующим updatedAt всей цели. Более позднее независимое изменение цели со старым контекстом может победить: отдельного журнала конфликтов поля пока нет. Старый клиент сам по себе ещё может записать JSON без поля; защита legacy действует в обновлённом коде.
