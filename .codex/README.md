# KODA subagents

Проектная настройка: `config.toml` регистрирует `qa`, `data_reliability`, `ui_ux`; файлы `agents/*.toml` задают модель, reasoning, инструкции, sandbox и отключают дальнейшее делегирование. Правила выбора ролей находятся в корневом `AGENTS.md`. Глобальные настройки не менялись.

| Роль | Модель | Reasoning | Режим по умолчанию |
| --- | --- | --- | --- |
| qa | gpt-6-luna | medium | read-only |
| data_reliability | gpt-6-astra | high | workspace-write |
| ui_ux | gpt-6-luna | high | workspace-write |

Модель координатора наследуется. Лимит — два субагента, основной агент не учитывается. Luna выбрана для ограниченных проверок и UI-задач; Astra — для более сложной логики данных. Эти модели и уровни присутствуют в локальном каталоге установленного клиента; доступность может меняться.

## Ограничение текущего механизма запуска

Текущий `collaboration.spawn_agent` не имеет параметра выбора нативной роли; то же ограничение подтвердил отдельный ephemeral CLI probe. Поэтому пробный запуск использовал настоящий субагент с явной моделью/effort и поручением прочитать инструкции `qa.toml`, а не автоматическое применение TOML-слоя. Называть это проверкой автоматической загрузки роли нельзя.

`AGENTS.md` предписывает такой совместимый запуск при отсутствии селектора роли. В этом варианте ограничения записей и запрет вложенного делегирования передаются инструкциями, а sandbox наследуется от основной сессии. Координатор обязан соблюдать лимит 2 сам. Когда инструмент поддерживает выбор роли, использовать его и нативные настройки; режим разрешений основной сессии всё равно может переопределять sandbox роли.

Для перечитывания проектной конфигурации нужен новый сеанс Codex в этом проекте. Это не гарантирует появления отсутствующего параметра выбора роли в установленной версии. В текущем чате совместимый запуск уже проверен. Codex не обновлялся и не перезапускался; новые инструменты не устанавливались. Проверка версии сообщила `restart_required` от ранее подготовленного обновления — это не результат этой настройки.
