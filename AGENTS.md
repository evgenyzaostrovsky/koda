# KODA: работа в проекте

Основной агент — разработчик и координатор: отвечает за интеграцию, исправление найденных ошибок и итоговую проверку. Сохраняй существующие изменения пользователя. Не публикуй приложение без авторизации в текущей задаче.

## Делегирование

- Сам выбирай и запускай нативных субагентов внутри текущей задачи; пользователю не нужно открывать отдельные чаты. Роли настроены в `.codex/agents/*.toml`.
- Небольшие локальные изменения выполняй и проверяй самостоятельно. Не запускай все роли на каждую задачу.
- `qa`: подключай после существенных изменений поведения и при повторяющихся ошибках. Проверяет независимо, код приложения не меняет.
- `data_reliability`: подключай при изменении сохранения, истории, офлайн-режима, синхронизации или конфликтов устройств. Выдавай точную область и разрешённые файлы. Схема БД и рабочие данные требуют отдельного разрешения пользователя; по умолчанию локальная/тестовая среда.
- `ui_ux`: подключай при существенных изменениях интерфейса или конкретной проблеме удобства. Выдавай экран/сценарий и разрешённые компоненты; сохраняй стиль, если не заказан редизайн.
- Не более двух субагентов одновременно. Помощникам запрещено создавать дополнительных агентов, делегировать через CLI/API или открывать отдельные задачи; в их конфигурациях `agents.enabled = false`.
- Параллельно выполняй только независимые задачи. Никто, включая координатора, не редактирует одновременно одни файлы. Браузерные проверки одной вкладки также выполняй последовательно.
- Итоговое поведение проверяй после интеграции. Возвращай найденные ошибки исполнителю в существующую подзадачу, если это экономнее нового запуска.

## Короткое поручение каждому субагенту

Передай: **цель; границы и запрещённые действия; файлы для чтения и разрешённые для записи; критерии готовности; проверки/среда; ожидаемый отчёт**. Передавай нужный diff, решения и уже полученные результаты, а не всю переписку. Используй минимальный `fork_turns`, если механизм запуска это поддерживает.

Отчёт: **результат; изменённые файлы; выполненные проверки; ошибки; ограничения**. Отличай воспроизведённое от предположений и непроведённых проверок. Не выдавай чтение кода за проверку работающего приложения.

## Экономия и проверка

- Модели ролей: `qa` — `gpt-6-luna`/`medium`; `ui_ux` — `gpt-6-luna`/`high`; `data_reliability` — `gpt-6-astra`/`high`. Модель координатора не меняй. Простые исправления делай сам; сильную роль используй для действительно сложной логики данных. Не повышай effort автоматически.
- Предпочитай нативный выбор роли. Если инструмент не имеет параметра роли (проверено для CLI `0.158.0-alpha.2`), запускай настоящего субагента через доступный `spawn_agent`: явно передай модель/effort из соответствующего TOML, его инструкции и поручение; используй `fork_turns="none"`. Это совместимый запуск, а не подтверждение автоматического применения TOML. Лимит двух и запрет вложенного делегирования соблюдай явно; sandbox роли при таком запуске не гарантирован. Не заменяй роль неизвестной моделью.
- Сначала используй уже полученные выводы и точечный поиск. Не повторяй исследования/проверки без причины. Повторная проверка нужна после изменения относящегося к ней кода, сбоя или недостаточных доказательств.
- Передай QA окончательный diff и результаты исполнителей. Не запускай независимую проверку ещё меняющегося поведения.
- Доступные проверки: `npm run typecheck`, `npm test` и отдельные `test:*` из `package.json`. Выбирай по риску изменения; для настройки агентов не запускай сборку/тесты приложения без необходимости.
- Предпочитай существующее локальное превью. Проверки с записью выполняй на тестовых данных; не меняй реальные записи пользователя ради теста.
